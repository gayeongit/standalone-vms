# VMS v2 미결 항목 — 결정 대기 목록

- 최종 갱신: 2026-03-06
- 상태: Phase 1(렌더링)은 독립 착수 가능. **Phase 2+(통신) 이전에 확정 필요**

> Phase 1(StreamPlayerV2)은 아래 미결 항목과 무관하게 즉시 착수 가능합니다.
> Phase 2 이후 항목은 미결 시 재작업 확률이 높습니다.
> 🔴 = 구현 블로커, 🟡 = 블로커는 아니나 조기 확정 권장, 🟢 = 나중에 해도 됨

| **운영 정책** | UGV 구현 마지막 단계에서 재검토/확정 (현재 보류) |

## C. 결정 완료 항목

### C-1. 🟢 JWT refresh 정책 (완료)

| 항목 | 내용 |
|------|------|
| 결정 | refresh 메커니즘 없이, **로그아웃 또는 앱 종료 시 토큰을 폐기** |
| 영향 | 서버는 토큰 만료를 길게(예: 24시간) 주거나 만료 없이 발급하고, 로그아웃 시 무효화 정책 적용 |
| 조치 | 아키텍처 문서에 "향후 보안 강화 시 참고"용 refresh 확장 범위를 보존 |

### C-2. 🟢 CCTV 제어 REST 엔드포인트 (완료)

| 항목 | 내용 |
|------|------|
| 결정 | `POST /channel/{channelId}/zoom`, `POST /channel/{channelId}/focus` |
| Body | `{ "value": -100|-10|-1|1|10|100 }` |
| 매핑 | 서버 내부에서 CGI `Zoom`/`Focus` 값으로 변환 호출 |
| 상태 | `focus/reset`은 v2 초기 스코프 보류 (후속 확장 후보) |

### C-3. 🟢 테스트 운영 정책 (완료, 13.11 반영)

| 항목 | 내용 |
|------|------|
| 결정 | Phase 게이트 방식으로 최소 스모크 테스트 운영 |
| 규칙 | 각 Phase 완료 시 스모크 실행, 실패 시 다음 Phase 진행/머지/배포 중지 후 디버깅 |
| 최소 시나리오 | 로그인→DeviceCheck, DeviceCheck→Main, RTSP 1채널 재생/정지, 스냅샷 저장, 클립 파일 생성, Playback 타임라인 1회 조회 |

### C-4. 🟢 설정 반영 정책 (완료, 13.12 반영)

| 항목 | 내용 |
|------|------|
| 결정 | `snapshotDir`/`clipDir` 즉시 반영, 수동 RTSP 추가/삭제 즉시 반영 |
| 보류 | ONVIF Discovery 기능은 서버 협의 전까지 보류 (기능 제외 가능성 포함) |
| 운영 정책 | TLS 관련 세부 설정은 현재 추가 정의 없이 운영 이슈 발생 시 이슈 등록 후 수정 |

### C-5. 🟢 FFmpeg 정책 (완료, 13.13 반영)

| 항목 | 내용 |
|------|------|
| 결정 | 번들 배포 + installer 방식 확정 |
| 체크 시점 | 앱 시작 직후 ffmpeg 헬스체크 |
| 실패 처리 | ffmpeg 의존 기능(클립/Export)만 비활성화, 툴팁 `FFmpeg을 찾을 수 없습니다` |
| 테스트 | 개발 착수 전 실패 경로 1회, 릴리즈 직전 클린 환경(E2E) 1회 |

### C-6. 🟢 이벤트 UX 정책 (완료)

| 항목 | 내용 |
|------|------|
| 결정 | Topbar 알림센터(벨) 공통 고정 + 신규 이벤트 빨간 점 배지 |
| 검색 | 이벤트 검색 버튼은 Topbar 공통 버튼으로 이동 (기존 검색 모달 재사용) |
| 화면 정책 | Main만 이벤트뷰 토글 제공, CCTV 이벤트뷰 제거, UGV/Playback은 알림센터로 확인 |
| 알림 방식 | 기존 스낵바 이벤트 알림은 폐기 |

### C-7. 🟢 WS 인증 방식 (완료)

| 항목 | 내용 |
|------|------|
| 결정 | WS 핸드셰이크 HTTP 헤더에 `Authorization: Bearer <token>` 사용 |
| 영향 | 쿼리 토큰/auth 초기 메시지 방식 미사용 |
| 비고 | REST와 동일한 인증 전달 방식으로 통일 |

### C-8. 🟢 WS 공통 필드/응답 규칙 (완료)

| 항목 | 내용 |
|------|------|
| 공통 필드 | `type`, `msgId`, `ts`, `payload`, `error` |
| 요청/응답 매칭 | `msgId` 단일 키로 통일 (`reqId` 미사용) |
| 응답 규칙 | 요청 메시지에 대해 `*.ack` / `*.nack` 사용 |
| nack 규칙 | `error.code`, `error.message` 필수 |
| 비고 | CSV 오탈자(`eventDetaile`)는 서버/클라이언트 매핑 시 정정 |

### C-9. 🟢 로그인 토큰 키 (완료)

| 항목 | 내용 |
|------|------|
| 결정 | 로그인 응답 토큰 키는 `accessToken`으로 고정 |
| 처리 | CSV의 `assessToken` 표기는 오타로 간주 |
| 조치 | 클라이언트 파서는 `accessToken` 기준으로 구현 |
